# Debugging SFNO Training: Stage 0 

A simple SFNO(spherical fourier neural operator) is used to learn SWE on the sphere(500hPa ERA5 data). However, the current model is extremely unsatisfactory. The most noticable behaviour is that
1. The mean error(relative MSE computed on grid space) is extremely high, settles around 60%
2. The prediction has no visible clues of proper dynamics, e.g., a vortex advected from it's starting position to a new position, the rotation of a vortex 
3. The model is overfitting and has a gibbs like ringing pattern 
4. Autoregressive rollout quickly explodes as a result of the incorrect prediction

## The current workflow
The current workflow is largely characterized by
1. Trained on 500hPa data generated by a psuedospectral solver(`src/numerical_solver/psuedo_spectral_solver_naive.py`) with ERA5 data as initial condition. The variables are $(\Phi, \zeta, \delta)$(geopotential, vorticity and divergence). Some details(*verify* with my code):

- Actual data is a just a pair $(x(t),x(t+\delta t))$ where $\delta t$ is  `n_future * 30` minutes. 
- The sampling is restricted to a window $[t_0+A,t_{end}]$ where $A$ is a constant(usually 1~3 days).


2. The model architecture is:
```
self.model = SFNO(
    img_size=(self.nlat, self.nlon), grid=self.ds.solver.grid,
    num_layers=num_layers, scale_factor=scale_factor, embed_dim=embed_dim,
    residual_prediction=residual_prediction,
    pos_embed=pos_embed, use_mlp=True,
    normalization_layer=self.normalization_layer,
).to(self.device)
```
with a config of something like
```
# configuration for make train_single
train_single:
  # The training set directory
  training_data_dir: "model_output/numerical/resol_64/tau_(30000,2,2)/grid_eq/method_implicit/radiation_no_rad/duration_20/ic_rw/pressure_500/dataset_1980_2025_odd_month_500/"
  batch_size: 128
  lr: 8e-4
  n_future: 48
```

3. The loss function is a physical loss function on the grid space computing relative MSE. 


## Possible Causes
1. **(Double-check if what I'm claiming is true indeed)**  I suspect that the model architecture is slightly different from the original fourier/spherical fourier neural operator. Specifically, the original architecture vaguely resembles:
$$
\sigma(\mathrm{Decoder}(\mathrm{Encoder}(x)+Wx))+x
$$
with no 
```
inner_skip="linear"
```
in the initailization of the model, we don't have the $Wx$ term inside the activation function. This greatly limited the expressivity of the model. 

2. The training data is model generated and is possiblly polluted with numerical artifacts(Gibbs Phenomenon). 
- The PS solver uses ERA5 on a finer grid then specified by the solver. Hence a spectral truncation is used which can cause Gibbs phenomenon. Although we gave the solver some time to damp the ringing by sampling from $t_0+A$, the artifact might still get into the training process and overwhelm the actural training signal.
